## 🔄 两模组如何互通

合并后的设计原则是**只有一套系统**。两个模组的内容共用同一个事件表、同一个调度器、同一份配置、同一套命令，
因此它们可以互相触发、统一开关、统一调强度：

| 维度 | 合并前 | 合并后 |
|---|---|---|
| 事件表 | mindbreak 自己一个 `ChaosEvents` 列表（43 个）<br>zhengren 一个 `TrollRegistry`（571 个） | **一个 `TrollRegistry`，共 2000 个事件**（合并时 615，扩容 +1385），全部可被 `/zr list`、`/zr info`、`/zr fire` 操作 |
| 调度 | mindbreak 每 20 tick 掷概率（7%/10%/13%）<br>zhengren 按权重+冷却+等级+崩溃指数抽取 | **只有 `TrollScheduler` 一套**。精神污染事件带自己的权重/冷却/等级，参与同一套加权抽取，受崩溃指数与每分钟限流约束 |
| 延时任务 | mindbreak 有 `ChaosScheduler`<br>zhengren 没有 | **提升为公共能力 `DelayScheduler`**，通过 `ctx.later(ticks, action)` 暴露给全部 2000 个事件 |
| 配置 | 两个模组各自的开关/强度 | **一份 `config/zhengren.json`**：`enabled`、`mindbreakEnabled`、`mindbreakIntensity`、`mindbreakHooks`、`chatMangle`、黑名单等统一生效 |
| 命令 | `/zr` 与 `/mindbreak` 两套状态 | `/zr` 与 `/mindbreak`（别名 `/mb`）**共享同一份状态**；`/zr` 新增 `intensity`、`gift` |
| 物品 | mindbreak 五件神器，只驱动自己的随机逻辑 | 五件神器注册在 `zhengren` 命名空间，`离谱棒` 直接触发**统一事件表**里的随机事件（可能触发整人大师的原生事件） |

**具体的互通点：**

1. **精神污染事件进入统一事件表** —— `TrollEvents.bootstrap()` 调用 `MindbreakEvents.register()`，44 个事件以分类 `精神污染` 注册进 `TrollRegistry`，总数 571 → **615**；后续扩容批次再并入 14 个新分类 1385 个事件，最终 **2000**。
2. **强度实时生效** —— `TrollScheduler.pick()` 对分类为 `精神污染` 的事件按 `mindbreakIntensity`（1/2/3 → 0.5×/1×/2×）实时缩放权重，改强度不用重启。
3. **开关统一** —— `mindbreakEnabled=false` 时精神污染事件退出随机调度（仍可 `/zr fire` 手动触发）；总开关 `enabled=false` 则全部停止。
4. **反向赋能** —— 至少 3 个精神污染事件改用了整人大师独有、mindbreak 原本没有的能力（客户端假崩溃/黑屏 `ctx.glitch`、假成就弹窗 `ctx.fakeAchievement`、标题 `ctx.title`、陨石雨 `ctx.meteorShower` 等）。
5. **桥接事件 `relic_gift`** —— 随机事件也能直接把五件神器塞进玩家背包。
6. **交互回调统一管控** —— 原 mindbreak 的 8 个交互回调（挖方块被拒、方块变身、床拒绝你、打怪背刺、聊天被曲解、死亡遗言、加入/重生问候）全部受 `enabled` + `mindbreakEnabled` + `mindbreakHooks` + `chatMangle` 约束；**原先那套独立的 tick 概率轮询已彻底删除**。

### 与原 mindbreak 的差异（升级须知）

- MC 版本从 1.21.1 降到 **1.20.1**（以整人大师为基线，因为 1.20.1 侧有 57 万字节的既有事件代码与已验证的构建环境）。
- 物品命名空间从 `mindbreak:` 改为 **`zhengren:`**，配方目录从 `data/mindbreak/recipe/`（1.21 单数）改为 `data/zhengren/recipes/`（1.20.1 复数），配方 JSON 格式同步转换为 1.20.1 语法。
- 原 mindbreak 的 `ChaosManager`（独立开关/强度/计数）、`ChaosEvents`（独立事件列表）、`ChaosScheduler`（已升级为公共 `DelayScheduler`）不再作为独立系统存在。
- 旧存档里的 `mindbreak:` 物品会变成未知物品 —— 这是跨模组合并的必然代价。

## 😈 这是什么

你有没有想过：为什么《我的世界》这么温柔？

这个模组就是为了回答这个问题。装上它之后，你在游戏里做的每一件事都可能被"温柔地打断"——

脚底下的方块会突然消失，背后的苦力怕引信声永远没有苦力怕，
背包每五分钟洗一次牌，床没了，天黑了，然后**你的屏幕显示游戏崩溃了**（其实并没有）。

**没有尺度，没有下限，只有越来越多的整人事件。**

而且它会越来越狠：随着你被整的次数增加，**崩溃指数**会不断攀升，事件间隔自动缩短、残酷等级自动提升。
你越忍，它越过分。

## 🔨 从源码构建

```bash
# 需要 JDK 17
cd zhengren-mod
./gradlew build        # Windows: gradlew.bat build
```

产物：`build/libs/zhengren-3.0.1.jar`

### Linux / 中文路径环境的两个坑（合并时实际踩到并已修好）

1. **必须设置 UTF-8 locale**。如果工作目录路径含中文（例如 `/.../整人模组工作区/zhengren-mod`），
   在 `LANG` 为空的容器里 JVM 的 `sun.jnu.encoding` 会退化成 ASCII，Gradle 启动直接抛
   `InvalidPathException: Malformed input or input contains unmappable characters`。构建请用：

   ```bash
   export LANG=C.UTF-8 LC_ALL=C.UTF-8
   JAVA_HOME=/usr/lib/jvm/java-17-openjdk-arm64 ./gradlew build
   ```

2. **`authlib` / `text2speech` 需要 Mojang 官方源**。BMCLAPI 镜像对这两个坐标返回 403，
   `build.gradle` 里已显式加入 `https://libraries.minecraft.net/` 仓库兜底。

> 🧪 本项目使用 **Fabric Loom 1.6.12 + Gradle 8.7 + Yarn 1.20.1+build.10 + OpenJDK 17** 实际编译验证通过
> （`compileJava → processResources → jar → remapJar` 全绿，产物已重映射为 intermediary 命名空间）。
> ⚠️ Loom 1.6.12 与 Gradle 8.14+ 不兼容（`Problems.forNamespace` API 变更），请使用 wrapper 自带的 8.7。

**关于 `libs/fabric-api/`**：为了在**完全离线**的机器上也能构建，本项目把 Fabric API 0.92.12 的 53 个模块 jar
直接放在 `libs/fabric-api/` 下（由官方 fat jar 解包得到），`build.gradle` 用
`modImplementation fileTree(dir: 'libs/fabric-api', ...)` 引用，避免解析远端 POM 的 90+ 子模块。
如果你的网络正常，想换回标准写法，把那一行换成下面这行即可（同时需要把 `fabric_version` 写回 `gradle.properties`）：

```groovy
modImplementation "net.fabricmc.fabric-api:fabric-api:${project.fabric_version}"
```

> 📦 国内网络建议把 `gradle/wrapper/gradle-wrapper.properties` 里的 `distributionUrl` 换成镜像
> （本仓库默认已指向腾讯云镜像，首次构建快很多）。

## 🎮 指令

所有指令都注册了三个别名：`/zhengren`、`/zr`、`/troll`。

| 指令 | 作用 |
|---|---|
| `/zr` | 显示帮助与当前状态 |
| `/zr on` / `/zr off` | 开启 / 关闭整人模式 |
| `/zr reload` | 重新读取配置文件 |
| `/zr count` | 显示事件总数与各等级数量 |
| `/zr stats` | 显示自己的崩溃指数、累计被整次数、上一次事件 |
| `/zr rage` | 只看崩溃指数 |
| `/zr chaos [秒]` | **狂暴模式**：每 1 秒触发一次事件（默认 30 秒） |
| `/zr calm` | 停止狂暴模式 |
| `/zr mode <1-6>` | 设置最高残酷等级（1=只小整，5=允许地狱级，**6=允许绝望级**） |
| `/zr brutality [1-5]` | **残酷度总控（v3.0.0 新增）**：不带参数查看当前值，带参数设置。1→×0.5，5→×5（默认 5） |
| `/zr interval <最小秒> <最大秒>` | 设置随机事件的间隔区间 |
| `/zr damage <true\|false>` | 是否允许破坏地形类事件（默认 false） |
| `/zr list [页码]` | 分页列出全部事件 id |
| `/zr info <id>` | 查看单个事件的名称/等级/权重/冷却/说明 |
| `/zr fire <id> [玩家]` | 手动对某人触发指定事件 |
| `/zr random [玩家]` | 手动触发一个随机事件 |
| `/zr intensity <1-3>` | **「精神污染」强度**（合并新增）：影响那 44 个事件的抽取权重 |
| `/zr gift` | **领取五件精神污染神器**（合并新增）：离谱棒 / 嘴臭之书 / 混乱珍珠 / 后悔蛋糕 / 神秘不明肉 |

### `/mindbreak` 兼容指令（别名 `/mb`）

为兼容原 mindbreak 模组的操作习惯保留，**内部完全共用同一份状态**（与 `/zr` 改的是同一个 `config/zhengren.json`）：

| 指令 | 等价于 |
|---|---|
| `/mb toggle` | 切换 `mindbreakEnabled`（只关精神污染事件，不动总开关） |
| `/mb intensity <1-3>` | `/zr intensity <1-3>` |
| `/mb trigger <id>` | `/zr fire <id>`（含全部 2000 个事件，不限于精神污染） |
| `/mb list` | 只列出「精神污染」那 44 个事件 |
| `/mb gift` | `/zr gift` |
| `/mb chaos` | 随机连发 5 次统一事件表里的随机事件 |
| `/mb stats` | 事件总数 / 精神污染数量 / 强度 / 开关状态 |
| `/mb help` | 帮助 |

示例：

```mcfunction
/zr chaos 120          # 接下来两分钟，每秒整你一次
/zr mode 5             # 解锁全部地狱级事件
/zr interval 5 15      # 提高频率：5~15 秒一次
/zr fire chaos_ultimate_combo    # 手动体验终极连击
/zr fire glitch_total_meltdown @a # 让所有人体验假崩溃
/zr fire chat_spam     # 触发合并进来的精神污染事件
/zr intensity 3        # 精神污染事件权重 ×2
/zr gift               # 一次领全五件神器
```

## ⚙️ 配置文件

首次启动后生成于 `config/zhengren.json`：

```json
{
  "configVersion": 3,
  "enabled": true,
  "maxTier": 6,
  "minIntervalSeconds": 8,
  "maxIntervalSeconds": 30,
  "escalation": true,
  "announce": true,
  "allowWorldDamage": true,
  "affectCreative": true,
  "clientGlitches": true,
  "fakeKick": true,
  "maxEventsPerMinute": 40,
  "glitchPower": 1.0,
  "brutality": 5,
  "punishmentRider": true,
  "punishmentChance": 100,
  "chainChance": 45,
  "maxChainDepth": 3,
  "noMercy": true,
  "disabled": [],
  "targets": [],
  "mindbreakEnabled": true,
  "mindbreakIntensity": 2,
  "mindbreakHooks": true,
  "chatMangle": true
}
```

> ⚠️ **v3.0.0 起默认值就是「不留情」**：最高等级 6（绝望）、允许破坏地形、残酷度 5（×5）、
> 事件间隔 8~30 秒、每分钟上限 40、温和事件 100% 附带残酷惩罚、45% 连击、死亡后追击。
> 想给自己留活路就把 `brutality` 调小、`maxTier` 调到 3 以下、`allowWorldDamage` 关掉。

| 字段 | 类型 | 说明 |
|---|---|---|
| `enabled` | bool | 总开关，等同于 `/zr off` |
| `maxTier` | 1-6 | 允许出现的最高残酷等级（**6 = 绝望**） |
| `minIntervalSeconds` | int | 两次事件之间最小间隔 |
| `maxIntervalSeconds` | int | 两次事件之间最大间隔 |
| `escalation` | bool | 是否随崩溃指数自动加速、加重（v3.0.0 起压得更狠，最多压到 8%，下限 1 秒） |
| `announce` | bool | 是否在聊天栏提示"刚刚发生了什么" |
| `allowWorldDamage` | bool | 是否允许**大规模地形改造**（陨石雨的 TNT 模式、岩浆灌溉、大规模爆炸）。v3.0.0 起**默认开启** |
| `affectCreative` | bool | 是否整创造模式玩家 |
| `clientGlitches` | bool | 是否下发客户端画面整活 |
| `fakeKick` | bool | 是否允许"假掉线"类事件 |
| `maxEventsPerMinute` | int | 频率上限，防止事件太密导致卡顿 |
| `glitchPower` | 0.1-5.0 | 客户端画面整活强度倍率 |
| **`brutality`** | 1-5 | **残酷度总控（v3.0.0 新增）**：全局放大伤害、效果时长、爆炸威力、位移与物品损失。1→×0.5／2→×1／3→×1.8／4→×3／**5→×5（默认）** |
| **`punishmentRider`** | bool | **温和事件附带残酷惩罚（v3.0.0 新增）**：等级 ≤ 烦人的事件执行完后，额外抽一个重击 |
| **`punishmentChance`** | 0-100 | 惩罚附加的触发概率，默认 100 |
| **`chainChance`** | 0-100 | **事件连击概率（v3.0.0 新增）**：一个事件结束后有概率立刻再触发一个随机事件，默认 45 |
| **`maxChainDepth`** | 0-10 | 连击最多嵌套层数，默认 3 |
| **`noMercy`** | bool | **死亡后追击（v3.0.0 新增）**：玩家重生时立刻补一次残酷惩罚 |
| `disabled` | 数组 | **黑名单事件 id**，写进去的事件永远不会触发 |
| `targets` | 数组 | 只整这些玩家名；留空 = 整所有人 |
| `mindbreakEnabled` | bool | 「精神污染」事件是否参与随机调度（关掉后仍可 `/zr fire <id>` 手动触发） |
| `mindbreakIntensity` | 1-3 | 「精神污染」事件权重倍率：1→0.5×、2→1×、3→2×，**改完立刻生效** |
| `mindbreakHooks` | bool | 是否启用交互型整活（挖方块被拒、方块变身、床拒绝你、打怪背刺、死亡遗言、进出问候） |
| `chatMangle` | bool | 是否启用聊天内容扭曲（18% 概率被曲解后以你的名义发出） |

> 🩸 **`brutality` 怎么起作用**：它不是让事件变多，而是让**同一个事件更痛**。
> 伤害、药水效果时长与等级、爆炸威力、传送距离、抛飞力度、一次夺走的物品数，全部按倍率放大。
> 治疗反而会被**削弱**（`heal` 除以倍率）——残酷度 5 时你几乎治不回来。
> 另外 `/zr brutality <1-5>` 可以随时在游戏里改。

> 🔁 **从 v2.0.0 升级会自动迁移旧配置**
> `config/zhengren.json` 新增了 `configVersion` 字段。首次以 v3.0.0 启动时会执行一次迁移：
> 凡是**仍然等于 v2 旧默认值**的项会自动升级到 v3 的残酷默认值
> （`maxTier` 5→6、间隔 20/75→8/30 秒、每分钟上限 14→40、`allowWorldDamage` false→true）。
> **你手动改过的值不会被覆盖**（判断依据就是"是否仍等于旧默认值"）。
>
> ⚠️ 这一步很关键：如果不迁移，从 v2 升级的存档会因为 `maxTier=5` 而**永远抽不到那 258 个「绝望」事件**。
> 迁移会在日志里打印 `已把旧版默认配置迁移到 v3 残酷默认值`。
> 想手动确认：`/zr mode` 应显示 **绝望**，而不是「地狱」。

例：只想被"小整"和"烦人"级别整，并且讨厌假崩溃：

```json
{
  "maxTier": 2,
  "disabled": ["glitch_fake_crash_report", "glitch_total_meltdown"]
}
```

### 🧱 扩容批次（v2.0.0）

从 615 扩到 2000 事件时，新文件**刻意不 import 任何 `net.minecraft.*` 类型** —— 只用 `ctx.*` 门面方法、
`TrollPools.*` 常量池和 `GlitchIds.*`，与原有 14 个原生分类文件的写法完全一致。

这么做的好处是：**新事件不可能因为 Minecraft 版本 API 变动而编译失败**，只依赖项目自身的稳定门面。
因此每个文件都能用"只编译这一个文件"的方式秒级校验，并且强制以下自检：

- 事件数精确等于配额
- id 全部带本分类前缀且全局唯一
- `grep -c 'net\.minecraft'` 必须为 `0`
- `.desc()` / `.run()` / `.build()` 一个都不能缺

另外对**危险 API 做了等级约束**：改地形类（`boomDestructive` / `lavaPit` / `voidPit`）只允许出现在
`BRUTAL` 及以上；`GlitchIds.FAKE_CRASH` / `FAKE_BAN`（按钮真的会退出游戏）只允许 `APOCALYPSE`
（`FAKE_BAN` 至少 `NIGHTMARE`）。

> 想加自己的事件？照 `src/main/java/com/zhengren/trollmod/events/WorldEvents.java` 的写法，
> 在 `expansion/` 下新建一个类，`TrollEvents.category("你的分类")` 然后在 `register()` 里
> `TrollEvents.reg(TrollEvent.of(...).desc(...).run(ctx -> {...}).build())`，
> 最后在 `core/TrollEvents.java` 的 `bootstrap()` 里加一行调用即可。

### 🩸 v3.0.0「残酷化」做了什么

v2.0.0 的问题是有 49% 的事件偏轻（小整+烦人）。v3.0.0 从**四个层面**把它掰过来了：

| 层面 | 做法 |
|---|---|
| **引擎** | 新增 `brutality` 残酷度总控（默认 ×5）：**同一个事件，伤害、效果时长、爆炸威力、位移、一次夺走的物品数全部放大**；治疗反被削弱 |
| **等级重排** | 1764 个事件的等级整体上移，温和档从 987 个压到 250 个；新增第 6 档「绝望」 |
| **惩罚附加** | 等级 ≤ 烦人的事件执行完后，**100% 追加一次随机残酷惩罚**（`PunishmentPool`，40 种：夺装备、活埋、雷击三连、怪物小队、TNT 齐射、陨石、假崩溃、剥夺视野……） |
| **内容** | 脚本给 1326 个"文案很轻但等级被上调"的事件注入了残酷化尾巴；7 个 agent 随后重写高等级事件时又替换掉其中约 350 处（改为有心理弧线的桥段），最终源码保留 **974** 处标记尾巴；258 个「绝望」事件的文案与桥段**全部**重写为阴森版本（假希望、先给后夺、假救援、永恒折磨） |

再加上**事件连击**（45% 概率立刻再触发一个）与**重生不赦**（死一次逃不掉），
你现在面对的不是"偶尔被整一下"，而是**持续性的围剿**。

> 想把这些全关掉：`/zr brutality 1`、`/zr mode 3`、`/zr off`，或直接改 `config/zhengren.json`。

## 🧠 它是怎么工作的

```
每 20 tick（1 秒）
   └─ 遍历所有在线玩家
        └─ 到了触发时间？  → 是 → 按权重随机抽一个可用事件
                                （过滤：等级上限 / 黑名单 / 冷却 / 触发条件 / 不重复上次）
                                → 用 try/catch 安全执行
                                → 崩溃指数 += 等级 × 1.5
                                → 重新计算下次触发时间（受指数与狂暴模式影响）
```

- **崩溃指数**：`/zr stats` 查看。指数越高，间隔越短（最多缩短 65%）。
- **频率闸门**：`maxEventsPerMinute` 保证不会一口气刷爆你（除非你开狂暴模式）。
- **失败安全**：任何单个事件抛异常都只会被记录到日志，绝不会导致服务器崩溃。

## ❓ 常见问题

**Q：会不会毁掉我的存档？**
A：不会。模组**不会读写/删除任何存档文件**（世界文件夹、region 文件都不碰），所有整活都发生在游戏运行过程中。
唯一会留下痕迹的是"破坏地形"类事件（爆炸、岩浆、TNT、凋灵，以及 `allowWorldDamage=true` 时才解锁的大规模地形改造）——
它们炸的是**游戏里的方块**，不是你的硬盘。介意的话请提前备份世界，或设 `/zr damage false` 并拉黑相关事件。

**Q：我玩创造模式也被整？**
A：是的，默认如此。想要安静可以设 `"affectCreative": false`。

**Q：太狠了，怎么关？**
A：`/zr off`，或者 `/zr mode 1` 只保留小整，或者用 `disabled` 数组把讨厌的事件 id 全部拉黑。

**Q：只装服务端可以吗？**
A：可以。除了"画面崩溃 / 结局级画面"这两类（共 81 个）的画面效果以外，其它近 500 个事件全部正常生效。

**Q：为什么有些事件一直不触发？**
A：每个事件都有冷却时间、权重、触发条件（比如必须身上有物品），而且不会连续触发同一个事件。
用 `/zr info <id>` 可以看到它的冷却与说明。
